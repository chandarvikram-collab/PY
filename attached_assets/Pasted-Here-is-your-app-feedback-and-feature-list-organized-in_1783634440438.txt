## 6. Architecture & Settings Clean-Up

**The Goal:** Fix the foundational database architecture so users don't overwrite each other's data.

### ⚙️ Structural Overhaul

* **Database Isolation:** Right now, multiple users are manipulating the same data pool. The backend architecture must be refactored so that **every single user account points to its own unique database rows** (isolated user IDs).
* **Sign-Out Behavior:** When a user clicks "Sign Out", instantly wipe the local session cache and route them cleanly back to the Welcome/Auth Dashboard.
* **Settings Consolidation:** Clean up the UI clutter. Move **Recalculate Targets**, **Username Updates**, and **Log Out** directly inside the new Settings menu.
* **Deprecation:** Completely remove the "Help & Support" button for this version.

## How to Shift This from Demo to Real (Production)

To get this app running for you, your dad, and real users, your development stack needs to pivot away from static, hardcoded demo files:

1. **Database & Auth (The Backbone):** Move your data to a backend platform like **Supabase** or **Firebase**. This natively handles unique user authentication, ensures your dad's data doesn't overwrite yours, and keeps usernames unique.
2. **Storage:** Use an object storage bucket (like Supabase Storage or AWS S3) to host the images for your calorie tracker, progress photos, and social feed videos.
3. **API Logic:** Connect your "AI Plan" generator to a structured LLM API call that returns strict JSON data containing *all* exercises and target adjustments, rather than just returning a single string that breaks your state.
4. **Payments:** Set up a free Stripe Developer account, input your API keys into your app, and use Stripe webhooks to automatically flip a user's database status to `is_premium = true` upon a successful $7.99 checkout.
